## The operators

| Operator | Meaning | Example result |
| --- | --- | --- |
| `+` | add | `7 + 2` is `9` |
| `-` | subtract | `7 - 2` is `5` |
| `*` | multiply | `7 * 2` is `14` |
| `/` | true division | `7 / 2` is `3.5` |
| `//` | floor division | `7 // 2` is `3` |
| `%` | remainder | `7 % 2` is `1` |
| `**` | power | `7 ** 2` is `49` |

The multiplication sign is `*`, not `x`, and exponentiation is `**`, not `^`.
In Python `^` means *exclusive or*, which operates on booleans and is a
different tool entirely.

<Callout kind="note" title="The operator to know early">
  `%` on integers is the modulo operation, and it is how you test divisibility
  and wrap values around. `number % 2 == 0` means *even*; `index % len(items)`
  means *wrap around the list*.
</Callout>

## Float precision is real, and it is not a bug

```python
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
```

The first line prints `0.30000000000000004`. The second prints `False`. This is
not Python being sloppy. Floats store a binary approximation of the decimal
value, and the approximation of `0.1` is not exact, so the errors survive the
addition.

Every language with binary floating point has this property. Professional code
does not fight it; it chooses the right tool for the job.

## Rounding and converting

There are three related operations, and they are not interchangeable.

```python
value = 3.14159

print(int(value))
print(round(value))
print(round(value, 2))
print(f"{value:.2f}")
```

`int` truncates toward zero and always returns an integer. `round` returns the
nearest value, and with a second argument it keeps that many decimal places.
The f-string `:.2f` formats without changing the underlying value, which is
what you want for display.

<Callout kind="watch" title="Banker's rounding">
  Python's `round` uses *banker's rounding*: exactly halfway cases go to the
  nearest even number. `round(2.5)` is `2`, and `round(3.5)` is `4`. If your
  domain expects half-up rounding, use `decimal.Decimal` with an explicit
  rounding mode instead of fighting the default.
</Callout>

## Integer division has a direction

Floor division rounds **down**, which matters the moment negatives appear.

```python
print(-7 // 2)
print(-7 / 2)
print(-7 % 2)
```

The first is `-4`, the second is `-3.5`, the third is `1`. Python guarantees
that `a == (a // b) * b + (a % b)`, so the remainder always has the same sign as
the divisor. That guarantee is worth remembering before you write your own
modulo function.

## Exact decimal arithmetic

For money and anything where rounding errors compound, Python ships
`decimal.Decimal`, which stores base-ten digits exactly.

```python
from decimal import Decimal

total = Decimal("0.1") + Decimal("0.2")
print(total)
print(total == Decimal("0.3"))
```

Both lines behave as you would want. The string argument matters: `Decimal(0.1)`
imports the binary approximation you were trying to avoid.

<Callout kind="try" title="Three experiments">
  ```python
  print(10 / 3, 10 // 3, 10 % 3)
  print(2**100, type(2**100))
  print(round(2.675, 2))
  ```

  The last line is famously `2.67`, not `2.68`, and the reason is binary
  representation rather than rounding. Working out why is the exercise.
</Callout>

<Callout kind="recap" title="Recap">
  Six operators do the work, with `/` always returning a float and `**` for
  powers. Floats are binary approximations, so `0.1 + 0.2` is not exactly
  `0.3`; use `Decimal` when that matters. `int` truncates, `round` rounds, and
  an f-string formats for display without changing the value.
</Callout>

## The smallest useful CLI

```python
import argparse

parser = argparse.ArgumentParser(description="Count words in files")
parser.add_argument("paths", nargs="+", help="files to read")
parser.add_argument("-n", "--number", type=int, default=5, help="top N words")
parser.add_argument("--ignore-case", action="store_true")

args = parser.parse_args()
```

```bash
python words.py notes.txt report.txt --number 3 --ignore-case
python words.py --help
```

`--help` is free, correctly formatted, and better documented than most hand
written usage messages.

## The argument types do the work

```python
parser.add_argument("--ratio", type=float)
parser.add_argument("--tag", action="append")
parser.add_argument("--mode", choices=["fast", "safe"], default="safe")
parser.add_argument("-v", "--verbose", action="count", default=0)
```

`type=float` means an invalid value fails before your code runs, with a message
naming the argument. That is validation you do not have to write. `action="append"`
collects repeated options into a list, and `action="count"` turns `-vvv` into
`3`.

## Subcommands

```python
sub = parser.add_subparsers(dest="command", required=True)

build = sub.add_parser("build", help="build the site")
build.add_argument("--out", default="dist")

serve = sub.add_parser("serve", help="serve locally")
serve.add_argument("--port", type=int, default=8000)

args = parser.parse_args()
if args.command == "build":
    build_site(args.out)
```

This is the shape of every modern CLI: a verb, then its own options. Dispatch on
`args.command` and keep each branch small.

<Callout kind="note" title="Exit codes are part of the interface">
  ```python
  if not args.paths:
      parser.error("at least one path is required")
  ```

  `parser.error` prints a usage message and exits with status 2. Returning 0 for
  failure breaks every script that calls yours; `raise SystemExit(1)` after
  printing to stderr is the manual version.
</Callout>

<Callout kind="try" title="Write the help first">
  Add every argument and run `--help` before writing any logic. If the help text
  is confusing, the interface is confusing, and no amount of code will fix it.
</Callout>

<Callout kind="recap" title="Recap">
  `argparse` gives you parsing, validation, help and exit codes. Let `type` and
  `choices` reject bad input early, use subcommands for verbs, and treat the
  help output as part of the design.
</Callout>
